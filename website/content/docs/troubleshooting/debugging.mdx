## Overview

When something goes wrong with rube-goldberg TUI, systematic debugging helps identify the root cause quickly. This guide covers the diagnostic tools and techniques available.

<Callout type="tip">
Start with the simplest diagnostic (logs) before moving to more complex debugging. Most issues can be resolved by examining iteration output.
</Callout>

---

## Iteration Logs

rube-goldberg TUI automatically saves output from each iteration to the `.rube-goldberg-tui/iterations/` directory.

### Viewing Logs

```bash
# View the most recent iteration
rube-goldberg-tui logs

# View a specific iteration
rube-goldberg-tui logs --iteration 5

# View logs for a specific task
rube-goldberg-tui logs --task US-005

# View full output without truncation
rube-goldberg-tui logs --iteration 5 --verbose
```

### Log File Location

```
.rube-goldberg-tui/
└── iterations/
    ├── iteration-001.json
    ├── iteration-002.json
    └── ...
```

Each log file contains:
- Task ID and details
- Full agent stdout/stderr
- Timestamps and duration
- Exit codes and completion status

### Searching Logs

```bash
# Search for errors across all iterations
grep -r "error" .rube-goldberg-tui/iterations/

# Find completion tokens
grep -r "COMPLETE" .rube-goldberg-tui/iterations/

# Search for specific task mentions
grep -r "US-005" .rube-goldberg-tui/iterations/
```

### Cleaning Up Logs

Old logs can accumulate and consume disk space:

```bash
# Preview what would be deleted
rube-goldberg-tui logs --clean --keep 10 --dry-run

# Delete old logs, keeping the 10 most recent
rube-goldberg-tui logs --clean --keep 10
```

## Session Inspection

The session file (`.rube-goldberg-tui-session.json`) contains the complete state of your rube-goldberg TUI session.

### Viewing Session State

```bash
# Quick status check
rube-goldberg-tui status

# JSON output for scripting
rube-goldberg-tui status --json

# Raw session file (when rube-goldberg-tui isn't running)
cat .rube-goldberg-tui-session.json | jq .
```

### Session File Structure

```json
{
  "version": "1.0.0",
  "startedAt": "2024-01-15T10:30:00Z",
  "currentIteration": 5,
  "taskStatuses": {
    "US-001": "completed",
    "US-002": "in_progress",
    "US-003": "pending"
  },
  "activeTaskId": "US-002",
  "lockPid": 12345
}
```

### Common Session Issues

<TabsRoot defaultValue="stale-lock">
  <TabsList>
    <TabsTrigger value="stale-lock">Stale Lock</TabsTrigger>
    <TabsTrigger value="corrupted">Corrupted State</TabsTrigger>
    <TabsTrigger value="missing">Missing File</TabsTrigger>
  </TabsList>
  <TabsContent value="stale-lock">
    If the `lockPid` refers to a dead process:

    ```bash
    # Check if the process exists
    ps -p $(cat .rube-goldberg-tui-session.json | jq -r '.lockPid')

    # Force resume if it doesn't
    rube-goldberg-tui resume --force
    ```
  </TabsContent>
  <TabsContent value="corrupted">
    If the session file is malformed:

    ```bash
    # Validate JSON syntax
    cat .rube-goldberg-tui-session.json | jq . 2>&1

    # Back up and recreate if corrupted
    mv .rube-goldberg-tui-session.json .rube-goldberg-tui-session.json.bak
    rube-goldberg-tui run --prd ./prd.json
    ```
  </TabsContent>
  <TabsContent value="missing">
    If the session file doesn't exist:

    ```bash
    # There's no session to resume - start fresh
    rube-goldberg-tui run --prd ./prd.json
    ```
  </TabsContent>
</TabsRoot>

## Configuration Debugging

### View Effective Configuration

```bash
# See the merged configuration from all sources
rube-goldberg-tui config show
```

This shows the final configuration after merging:
1. Default values
2. Global config (`~/.config/rube-goldberg-tui/config.toml`)
3. Project config (`.rube-goldberg-tui/config.toml`)
4. CLI flags

### Validate TOML Syntax

TOML syntax errors can cause configuration issues:

```bash
# Check for TOML parsing errors
cat .rube-goldberg-tui/config.toml | npx toml2json 2>&1
```

Common TOML mistakes:
- Missing quotes around strings with special characters
- Incorrect table nesting with `[section]`
- Using `=` instead of `:` (TOML uses `=`)

### Configuration Precedence

```
CLI Flags (highest priority)
    ↓
Project Config (.rube-goldberg-tui/config.toml)
    ↓
Global Config (~/.config/rube-goldberg-tui/config.toml)
    ↓
Default Values (lowest priority)
```

## Agent Debugging

### Verify Agent Installation

```bash
# List detected agents
rube-goldberg-tui plugins agents

# Test agent directly
which claude && claude --version
which opencode && opencode --version
```

### Test Agent Execution

Run the agent manually to isolate issues:

```bash
# Test Claude Code directly
echo "Say hello" | claude --print

# Test OpenCode directly
echo "Say hello" | opencode run
```

### View Agent Command

To see what command rube-goldberg TUI executes:

1. Check iteration logs for the full command
2. Look for the `command` field in log JSON

```bash
rube-goldberg-tui logs --iteration 1 --verbose | head -50
```

## Tracker Debugging

### prd.json Issues

```bash
# Validate JSON syntax
cat prd.json | jq . 2>&1

# Check task structure
cat prd.json | jq '.userStories[] | {id, title, passes, status}'

# Find blocked tasks
cat prd.json | jq '.userStories[] | select(.blockedBy | length > 0)'
```

### Beads Issues

```bash
# Check Beads status
bd doctor

# View all tasks in an epic
bd list --epic your-epic-id

# Check for blocked tasks
bd blocked

# Sync status
bd sync --status
```

### Beads-bv Issues

```bash
# Verify bv is available
which bv

# Check graph analysis
bv --robot-triage | jq '.quick_ref'

# View dependency cycles (can block progress)
bv --robot-insights | jq '.Cycles'
```

## Template Debugging

### View Current Template

```bash
# Display the active prompt template
rube-goldberg-tui template show
```

### Test Template Rendering

To see what prompt is actually sent to the agent:

1. Check iteration logs - the rendered prompt is included
2. Look for `prompt` or `input` fields in the log JSON

### Template Variables

Available Handlebars variables:
- `{{task.id}}` - Task identifier
- `{{task.title}}` - Task title
- `{{task.description}}` - Full description
- `{{task.acceptanceCriteria}}` - Acceptance criteria
- `{{recentProgress}}` - Cross-iteration context
- `{{epic.title}}` - Epic title (if using Beads)

## Progress File Debugging

The progress file tracks cross-iteration context.

### View Progress History

```bash
# View accumulated progress
cat .rube-goldberg-tui/progress.md

# Check file size (capped at ~50KB)
ls -la .rube-goldberg-tui/progress.md
```

### Reset Progress

If progress context is causing issues:

```bash
# Clear progress file
echo "" > .rube-goldberg-tui/progress.md

# Or remove entirely (will be recreated)
rm .rube-goldberg-tui/progress.md
```

## Common Debug Workflows

### Workflow: Task Won't Complete

<Steps>
  <Step title="Check iteration logs">
    ```bash
    rube-goldberg-tui logs --task TASK-ID --verbose
    ```
    Look for the `<promise>COMPLETE</promise>` token in output.
  </Step>

  <Step title="Verify template includes completion instruction">
    ```bash
    rube-goldberg-tui template show | grep -i "promise\|complete"
    ```
  </Step>

  <Step title="Test agent directly">
    Run the agent manually with the same prompt to see if it completes.
  </Step>

  <Step title="Check acceptance criteria">
    If criteria are impossible to meet, the agent may never signal completion.
  </Step>
</Steps>

### Workflow: Unexpected Behavior

<Steps>
  <Step title="Check configuration">
    ```bash
    rube-goldberg-tui config show
    ```
    Verify settings match your expectations.
  </Step>

  <Step title="Review session state">
    ```bash
    rube-goldberg-tui status --json
    ```
  </Step>

  <Step title="Examine recent iterations">
    ```bash
    rube-goldberg-tui logs --verbose
    ```
  </Step>

  <Step title="Check for dependency issues">
    ```bash
    # For Beads
    bd blocked

    # For prd.json
    cat prd.json | jq '.userStories[] | select(.blockedBy | length > 0)'
    ```
  </Step>
</Steps>

### Workflow: Agent Errors

<Steps>
  <Step title="Check agent is working">
    ```bash
    echo "Hello" | claude --print
    ```
  </Step>

  <Step title="Verify credentials">
    ```bash
    # Claude Code
    claude config show

    # Environment
    echo $ANTHROPIC_API_KEY
    ```
  </Step>

  <Step title="Check rate limits">
    Look for rate limit messages in iteration logs.
  </Step>

  <Step title="Review error handling config">
    ```toml
    [errorHandling]
    strategy = "retry"
    maxRetries = 3
    ```
  </Step>
</Steps>

## Reporting Issues

When reporting issues to GitHub, include:

1. **rube-goldberg TUI version:**
   ```bash
   rube-goldberg-tui --version
   ```

2. **Configuration (sanitized):**
   ```bash
   rube-goldberg-tui config show
   ```

3. **Relevant iteration logs** (remove sensitive data)

4. **Session status:**
   ```bash
   rube-goldberg-tui status --json
   ```

5. **Steps to reproduce** the issue

<Callout type="warning">
Before sharing logs, remove any API keys, passwords, or other sensitive information.
</Callout>
